# 新媒体运营工作流 V2（官方信源驱动版）

> 版本：V2.0 ｜ 适用范围：爆点新闻 / 热点资讯类新媒体账号
> 核心变化：从“全网随便抓”改为「央媒必选 + 分类官方 TOP10 + 交叉验证 + 全文采集」，把权威性、可溯源性、时效性和分发闭环放进流程本身。

---

## 0. 设计原则（先立规矩）

1. **权威优先**：信息源按可信度分级，央媒与官方机构为 A 级，行业媒体为 B 级，社交热榜为 C 级（仅作趋势参考，不作事实依据）。
2. **全文为王**：标题和摘要只用于初筛；进入选题池的候选必须抓取正文全文，禁止凭标题写内容。
3. **双源验证**：凡进入制作环节的新闻，必须有 ≥2 个独立信源（其中至少 1 个为央媒或官方机构），或 1 个官方信源 + 官方原文链接。
4. **可溯源**：每条产出必须带「来源链接 + 发布时间 + 引用数据出处」，无法溯源的素材一律丢弃。
5. **闭环反馈**：分发后的数据回流到选题与制作参数，流程每轮自动进化。

---

## 1. 总流程（四段 + 前置 + 闭环）

```text
[阶段0 前置配置]
      │
      ▼
[阶段1 信息收集] → 央媒10（必选）+ 赛道官方TOP10 + 平台热榜
      │              输出：标准化原始信息库（含正文全文）
      ▼
[阶段2 信息整合] → 清洗去重 → 交叉验证 → 分类打标 → 重要度排序 → 全文归档
      │              输出：情报简报 + 选题清单（A/B/C 分级）
      ▼
[阶段3 内容制作] → 选题确认 → 文案生产 → 海报/视频生产 → 合规审查 → 质检门
      │              输出：成品物料包
      ▼
[阶段4 分发与复盘] → 平台适配 → 排期发布 → 数据回收 → 复盘反馈
      ▲                                        │
      └────────────── 反哺阶段1/2/3 ────────────┘
```

---

## 2. 阶段0：前置配置（每次运行前必须确认）

| 配置项 | 说明 | 默认值 |
|---|---|---|
| 赛道 | 本次内容所属类别（时政/财经/科技/民生/文娱/体育等） | 财经/科技 |
| 目标平台 | 视频号、抖音、小红书、公众号等 | 视频号/抖音/小红书/公众号 |
| 时间窗口 | 只收窗口内的新增信息 | 最近 2 小时（可按需调） |
| 源矩阵 | 自动生成：央媒10 + 赛道官方TOP10 + 平台热榜 | 见附录 |
| 输出规格 | A类深度 / B类精简 / C类热榜 的占比与格式 | A≤5条、B≤5条、C=热榜 |
| 合规开关 | 金融/医疗/教育等强监管赛道必须开启 | 按赛道自动识别 |

---

## 3. 阶段1：信息收集（源矩阵 + 全文抓取）

### 3.1 源矩阵生成规则

每个赛道运行时，自动组装三类信源：

| 层级 | 信源 | 数量 | 是否必选 |
|---|---|---:|---|
| A级·央媒 | 人民日报、新华社、央视新闻、央广网、光明日报、经济日报、中国日报、科技日报、工人日报、中国青年报 | 10 | **必须全部收录** |
| A级·分类官方 | 该赛道对应的部委/监管/权威机构官网（如财经：央行、财政部、发改委、证监会、统计局等） | 10 | 必须收录 |
| B级·行业媒体 | 该赛道头部垂直媒体（财联社、36氪、虎嗅等） | 5-10 | 可选 |
| C级·平台热榜 | 微博、抖音、小红书热榜 | 3 | 仅作趋势参考 |

### 3.2 抓取规则

1. 按源矩阵并行抓取，单源超时 10 秒，失败记录日志但不阻断整体。
2. 抓取优先级：
   - 优先解析官方 RSS/Atom；
   - 无 RSS 的官网抓取“要闻/新闻发布”列表页 HTML，抽取标题 + 链接 + 时间；
   - 列表页前 N 条进入正文抓取队列。
3. **全文抓取**：进入选题池的候选（默认每源前 5 条、合计不超过 20 条）必须抓取正文全文（`<p>` 段落文本），存为 `fullText` 字段；摘要由正文前 200 字生成，禁止使用页面 description 冒充正文。
4. 字段标准化：`title / link / source / level(A/B/C) / publishedAt / collectedAt / category / fullText / summary / media`。
5. 去重前置：URL 归一化（去 `utm` 参数、去 `#`、域名小写），标题相似度 >0.9 视为重复。

### 3.3 输出

- `原始信息库.json`：标准化字段 + 正文全文
- `抓取日志.json`：各源成功/失败/条数，用于源质量监控

---

## 4. 阶段2：信息整合（交叉验证 + 选题决策）

### 4.1 清洗与去重

1. 删除无正文、无时间、无链接的条目；
2. 标题相似度去重（SimHash/编辑距离）；
3. 同事件多源报道合并为一组，保留最早发布时间与最高信源等级。

### 4.2 交叉验证（硬门槛）

| 验证等级 | 规则 | 是否进入制作 |
|---|---|---|
| 通过 | ≥2 个独立信源，其中 ≥1 个央媒/官方 | ✅ |
| 基本通过 | 1 个官方信源 + 官方原文可打开 | ✅（标记“单源”） |
| 不通过 | 仅社交热榜 / 单一下级媒体 | ❌ 只进 C 类热榜，不进 A/B |

### 4.3 分类打标

按赛道预设分类体系打标，例如：

- 时政：外交/法治/民生政策/应急/人事
- 财经：货币政策/监管/市场行情/公司动态/产业政策
- 科技：政策/前沿突破/产品发布/企业动态
- 民生：教育/医疗/住房/养老/交通

每条新闻必须同时标注：`类别 + 传播性评级（高/中/低）+ 影响面（全国/行业/圈层）`。

### 4.4 重要度排序

排序公式（0-100）：

```text
重要度 = 信源等级权重(30) + 时效权重(20) + 影响面权重(25) + 传播潜力权重(25)
```

- 信源等级：央媒/官方 30，行业头部 20，平台热榜 10；
- 时效：窗口内越新越高，超窗口直接扣至 0；
- 影响面：全国民生 25，行业 15，圈层 8；
- 传播潜力：沿用 33 维度传播性评分折算。

### 4.5 输出

- `情报简报.md`：按重要度排序，含来源、时间、正文摘要、验证状态
- `选题清单.json`：A类（深度）、B类（精简）、C类（热榜）三组候选

---

## 5. 阶段3：内容制作（文案 → 海报 → 视频 → 合规 → 质检）

### 5.1 选题确认

1. 从选题清单取 A/B/C 候选；
2. 人工或规则确认：是否符合账号定位、是否与近期发布重复、是否踩合规红线；
3. 确认后进入制作队列。

### 5.2 内容分级生产

| 类型 | 内容 | 产出物 |
|---|---|---|
| A类·深度 | 时政/财经等强信息类 | 完整布局：关键数据 + 市场影响 + 33维度传播性评估 + 分镜 + 视频文案 |
| B类·精简 | 八卦/娱乐/游戏/搞笑 | 内容概述 + 传播性评级 + 一句话钩子 |
| C类·热榜 | 微博/抖音/小红书 | 热度表格 + TOP10 话题概述 |

### 5.3 文案生产

1. 以正文全文为输入，禁止脱离原文；
2. 数据必须标注来源，禁止编造数字；
3. 按平台情绪切换：时政庄重、财经数据驱动（必含风险提示）、娱乐轻快、八卦悬念、游戏燃向、搞笑反转；
4. 生成：标题（3 备选）+ 口播稿 + 字幕稿 + 发布文案。

### 5.4 海报生产

1. 主标题 + 副标题（日期/档期）+ 核心数据 + 来源角标；
2. 背景按类别色系：时政深红、财经蓝、科技青、民生绿、文娱紫、体育橙；
3. 输出 SVG 源文件 + PNG 导出，尺寸按平台（视频号 1080×1440、抖音 1080×1920 等）。

### 5.5 视频生产

1. 口播稿转分镜表：镜号/时长/画面/口播/字幕/音效；
2. 每条新闻独立分镜 + 整体合并分镜；
3. 生成剪映/剪辑软件可导入的脚本文件；
4. 如配置 TTS/素材库，自动生成配音稿与画面提示。

### 5.6 合规审查（硬门）

- [ ] 央媒/官方口径核对（不扩大、不歪曲）
- [ ] 金融内容含风险提示；医疗内容不含疗效承诺
- [ ] 数据可溯源（链接可打开）
- [ ] 无侵权素材、无未授权肖像/音乐
- [ ] 标题无夸大、无标题党越界

### 5.7 质检门

任一不通过 → 打回对应环节并记录原因；通过 → 进入分发队列。

---

## 6. 阶段4：分发与复盘（闭环）

### 6.1 平台适配矩阵

| 平台 | 调性 | 标题字数 | 正文要点 | 话题标签 |
|---|---|---:|---|---|
| 视频号 | 权威/新闻感 | ≤20 | 导语→主体→结语 | 3-5个 |
| 抖音 | 强钩子/短平快 | ≤18 | 前3秒钩子 | 3-5个 |
| 小红书 | 种草/干货 | ≤20 | 痛点+信息差 | 5-8个 |
| 公众号 | 深度/长文 | ≤25 | 结构完整 | 3个 |

### 6.2 排期与发布

1. 按各平台黄金时段排期（如早 7-9 点、午 12-13 点、晚 18-22 点）；
2. 支持手动发布 / 半自动发布（生成待发布文案包）/ 全自动发布（接入平台 API 后）；
3. 发布包包含：标题、正文、话题、封面图、视频文件、发布时间。

### 6.3 数据回收

发布后 24/48/72 小时回收：播放、完播、点赞、评论、转发、涨粉、跳转。

### 6.4 复盘反馈（闭环）

1. 计算内容得分 = 互动率 × 0.4 + 涨粉效率 × 0.3 + 转化 × 0.3；
2. 提炼“高表现内容特征”（选题方向/标题句式/时长/封面风格）；
3. 回填到阶段0 的选题参数、阶段1 的源矩阵权重、阶段3 的文案模板；
4. 连续 3 期低分内容自动降权对应选题方向。
